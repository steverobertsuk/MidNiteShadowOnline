SmartAoE v1.0.3 fixes a crash reported by Pak on Discord. A Fireball macro run through SelectManager's `!forselected` stopped with "Cannot read properties of undefined (reading 'total')". There are no breaking changes.

## Change Log

### Changed

- The README and help handout explain that SelectManager's `!forselected` drops inline rolls, so rolls in a `!forselected` command should be written as `<<…>>`.

### Fixed

- **Inline rolls lost by another mod no longer crash SmartAoE.** `!forselected` sends the command on once for each selected token, but without the original message's inline rolls. A roll such as `--damageFormula1|[[(5+?{Cast at what level?})d6]]` reached SmartAoE with no result. SmartAoE now whispers which roll has no result and suggests `<<…>>` instead.
- **An argument with no value**, such as a bare `--instant`, no longer stops with "Cannot read properties of undefined (reading 'match')".

If you run SmartAoE through `!forselected`, write the roll with `<<…>>`, which SmartAoE rolls itself. A query such as `?{Cast at what level?}` is still asked once, so the slot level and the damage stay in step:

```
!forselected smartaoe {{
  --aoeType|circle, float
  --radius|20ft
  --dc|@{selected|spell_save_dc}
  --saveFormula|5eDEX
  --damageFormula1|<<(5+?{Cast at what level?|3|4|5|6|7|8|9})d6>>
  --damageType1|fire
}}
```
